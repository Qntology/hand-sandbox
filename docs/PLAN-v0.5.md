# noto-sandbox v0.5 — 내려놓기·리셋·적재 더미, 결정 모델 운반, 라이브 기록, 가려진 지형 탐색, 환경 N:N 물리와 벤치마크

작성일 2026-10-24. v0.4([`PLAN-v0.4.md`](PLAN-v0.4.md)) 위에 더했다. 물리 리서치·벤치마크·개선 기록은 [`research/effects.md`](research/effects.md)에 있다. 벤치마크는 시간 측정이 아니라 기준 점수 시험이다.

## 0. 요청과 반영

| 요청 | 반영 |
|---|---|
| 인벤토리 아이템을 명령으로 내려놓기 | 동사 "drop"(내려놓·내려두·버리·하역·비워, drop·put down·unload 등)을 사전에 추가, `Plan::Drop`, 퀘스트 단계 "내려놓기". "원목 1개 내려놔"(로봇 앞 땅, 다시 주울 수 있음), "베이스캠프에 다 내려놔"(가서 더미에 쌓음), 실을 것이 없으면 `nothing_to_drop` (1장) |

| 월드 리셋 · 신체 상태 리셋 | `world_reset`(같은 시드 처음 상태, 몸은 유지: 배터리·발열·마모·타격 수), `body_reset`(배터리·발열·마모 초기화, 월드·위치·적재함 유지). 왼쪽 ③ 월드 섹션의 두 버튼 |
| 베이스캠프에 쌓인 것이 안 보임 | 웨이포인트마다 더미(`Waypoint.stock`): 1·3인칭 화면에 깃발 옆 상자 더미, 탑뷰·미니맵 개수, 오른쪽 "보관 더미" 섹션 |
| endmill-sandbox의 결정 모델로 "2개를 못 들면 하나씩 왕복" | 게이트 결정(`noto-runtime::cargo`): 적재 한도·팔 힘·파지·짐 실은 경로를 게이트(값·한계·심각도 0–3·조치)로 보고 가장 나쁜 게이트의 가장 보수적인 조치를 고른다 — 그대로 싣기 / 왕복(들 수 있는 만큼 가져다 놓고 돌아옴, 최대 16회) / 쪼개기 / 거절 (2장) |
| 바위를 캐면 50%만 들어 옮기기 | 부술 수 있는 아이템(돌·석탄·철광석)은 양(amount)을 가진다. 팔이 한 덩이를 못 들면 깨서(`Action::Split`, 시간 ∝ 양^(2/3) / 채취 속도) 들 수 있는 조각(예: 50%)을 옮기고 나머지는 다시 가지러 온다. 최소 조각 0.125 |
| 재생 중 명령 입력 → 통합 테스트 3줄 자동 기록, 툴바 통일 | 재생 중에 낸 명령(입력줄 Enter 또는 툴바)은 라이브 월드에서 1 게임 촬영 → 2 ML 인식 → 3 ML 결정(명령 순간의 월드를 복제해 다시 수행 후 라이브 월드로 복귀)을 기록. 기록 중 명령은 대기열. `#tl-cmd`·`#tl-run`·`#tl-stop`과 "자동 기록"이 `.viewport-toolbar`로 이동 (3장) |
| 피로·하중·미끄러짐·관절 부하·자세 안정 리서치, 환경과 N:N, 벤치마크 기준 점수와 시험, 벤치맥싱 없이 실제 물리 엔진에 점진 적용 | 지면 8종 × 주행부의 마찰·구름 저항·보행 에너지(`noto_core::surface`), 감속기 수명 Miner 누적(`noto_core::wear`), 지면이 들어간 자세·접촉·적재(`balance`), 경로·에너지·관절 마모(`world-sim`). 환경 N:N 벤치마크 E1–E6 + 홀드아웃(`noto_core::effects`), 엔진 입력 출처와 채점 출처 분리를 소스 검사로 강제. 0 → 3단계 개선 기록 (5·6장) |
| 시야가 가려진 상황에서 찾기, 못 올라가는 곳·절벽·바다로 복잡도 | 험지 맵(`terrain: rugged`): 바다(만)와 해안(젖은 모래 1 m, 그 뒤 마른 모래), 절벽으로 둘러싸인 고원 2곳(하나는 트랙·다리만 오르는 15 cm/칸 경사로), 카메라보다 높은 암벽. 다음 최선 시점 탐색과 지형을 보는 삼각 측량 (4장) |

## 1. 내려놓기

- 월드: `Action::Drop { item, amount }` 1초. 웨이포인트 1.6 m 안이면 그 더미에, 아니면 로봇 앞 0.45 m 땅에 놓는다(다시 주울 수 있는 드롭). 부분 양(깬 조각)도 그대로 놓인다.
- 명령: "원목 1개 내려놔" → 원목 1개, "원목 내려놔" → 원목 전부, "다 내려놔" → 적재함 전부, 장소가 있으면 가서 놓는다. 해석 결과 표시는 "원목 ×1", "원목 전부", "적재함 전부".
- 오른쪽 패널: 행마다 버튼, "모두 내려놓기". 둘 다 같은 퀘스트 경로(`submit_plan`)로 들어가 퀘스트 패널·로그에 남는다.

## 2. 결정 모델 운반

endmill-sandbox의 게이트 결정을 운반에 옮겼다. 게이트마다 값·한계·심각도(0 통과 … 3 막힘)와 권하는 조치가 있고, 규칙은 "가장 심각한 게이트들의 조치 중 가장 보수적인 것"이다.

| 게이트 | 보는 것 | 조치 |
|---|---|---|
| 적재 한도 | 실은 짐 + 이번 것 / 한도 (퀘스트와 무관한 짐은 따로 표시) | 넘으면 왕복(이 퀘스트의 짐을 내려놓고 다시) 또는 쪼개기, 무관한 짐이면 "내려놓으라"는 안내와 함께 거절 |
| 팔 힘 | 한 팔·두 팔 들기 균형·관절 피크 | 못 들면 쪼개기(부술 수 있는 것) 또는 거절 |
| 파지 | 손 마찰 용량 / 필요 힘 | 못 잡으면 쪼개기 또는 거절 |
| 짐 실은 경로 | 짐을 실은 몸의 한계와 **지면마다 마찰·구동력 한계**로 목적지까지 길이 있는가 (v0.5 물리) | 없으면 왕복 또는 쪼개기 |

왕복: 들 수 있는 만큼 가져다 목적지 더미에 놓고 돌아온다(최대 16회). 퀘스트 결과에 왕복 횟수가 남는다.

## 3. 라이브 기록과 툴바

재생 중(▶)에 명령을 내면 그 명령이 통합 테스트로 기록된다. 1줄은 라이브 월드에서 퀘스트를 수행하며 찍고, 2줄은 키프레임을 ML이 분석하고, 3줄은 명령 순간의 월드 복제본에서 ML 결정이 다시 수행한 뒤 라이브 월드(그 사이 진행된 상태)로 돌아온다. 기록 중에 낸 명령은 기다렸다 이어서 기록되고, "중지"는 기록·대기열·퀘스트를 함께 멈춘다. 예전 방식(시드에서 새 월드로 세 번)도 그대로 돈다.

## 4. 가려진 지형과 탐색

- 지형: `TerrainKind::Rugged`. 바다는 들어갈 수 없고, 고원은 절벽(1 m 넘는 단차)으로 둘러싸여 바퀴는 못 오른다. 베이스캠프와 창고 사이 통로는 보호되어 늘 연결되고, 노드 종류마다 바퀴로 닿는 노드가 2개 이상 남는다(시드 1–12 시험).
- 탐색: 높이장 위의 시야 계산(viewshed)으로 본 칸을 기록하고, 다음 시점을 "새로 보이는 땅 / (이동 시간 + 둘러보기 비용)"으로 고른다. ML 결정에 `Explore`가 생겼고, 삼각 측량 이동은 시선과 경로가 막히면 반대쪽·짧은 쪽으로 바꾼다.

## 5. 환경 N:N 물리 (요약)

자세한 값·출처·식은 [`research/effects.md`](research/effects.md) 1–3장.

| 층 | 무엇 | 어디 |
|---|---|---|
| 환경 | 지면 8종(단단한 바닥·바위·흙·풀밭·자갈 패드·마른 모래·젖은 모래·바다) × 발·바퀴·트랙의 μ, Crr, 보행 η. 웨이포인트 패드는 자갈, 험지 해안은 젖은 모래 → 마른 모래 | `noto_core::surface`, `world_sim::Ground` |
| 접촉 | 필요 마찰 `|tan θ + a/(g cos θ)| + 자체 전단` / 가능 마찰. 넘으면 그 자세는 미끄러짐(불가능). 다리는 한 걸음 미끄럼 확률 | `balance::Body::solve`, `surface::contact` |
| 이동 | 칸마다 그 지면의 마찰·구동력 한계로 통과 여부, 출발·제동 가속은 지면 견인 한계 이하, 에너지 = 순항 전력 × 지면 계수 | `world_sim::nav`, `Body::planned_accel` |
| 액추에이터 | 발열(v0.4) + 감속기 수명 Miner 누적(평기어 서보·유성 QDD·사이클로이드), 관절 부하 지수 max(피크, RMS) | `noto_core::wear`, `World::wear`, `World::joint_load` |
| 몸 | 지면·경사별 적재(구동력 대 구름 저항), 넘어짐/미끄러짐 중 먼저 오는 것 | `Body::capacity_on`, `body::compute` |
| 기록 | 이동·채취 중 월드 상태를 벤치 시나리오로 채점해 SDS `balance|fx:<효과>|<지면>|<상태>`, 마모 `effort|wear|…`. API `physics_status` | `noto-runtime::mlsds`, `api` |

몸 상태 효과(오른쪽 위 신체 상태 칩): 미끄러짐 = 지면·마찰 이용률·미끄럼 확률, 하중 = 적재 여유·몸무게 대비 %, 피로 = 발열·수명 사용, 관절 부하 = 한계 대비 %(피크, RMS/연속), 자세 안정 = 넘어짐 여유와 미끄러짐 여유 중 먼저.

## 6. 벤치마크 (요약)

`cargo test -p noto-core --test effects_bench -- --nocapture`가 `[FX]`(셀), `[FX-SUM]`(시나리오), `[FX-HELD]`(홀드아웃)을 출력한다. 시나리오 E1 모래 해변 · E2 젖은 모래 10° · E3 오염 실험실 바닥 · E4 체중 40% 짐 · E5 바위 채취 · E6 풀밭 15°, 프리셋 4종 × 다리·바퀴·트랙. 기준(채점 전용): Hanson 1999(경사 RCOF), Beschorner 2016(미끄럼 비율), Rodríguez-Martínez 2019(모래 바퀴 견인), Lejeune 1998(모래 보행 에너지), Knapik & Reynolds(운반 하중), Middleton 2022(짐 보행 속도), Frey Law & Avin 2010(지구 시간), maxon 선정 규칙(게이트), v0.4 단일 원인 표(여유·피크). 엔진 파일에 이 출처 이름이 나오면 시험이 실패한다.

개선 기록(0 = v0.4 → 1 = 지면·접촉 → 2 = 마모 → 3 = 지면별 적재·넘어짐/미끄러짐): 다리 모래 51.8 → 74.3(중급)·46.9 → 69.4(고급), 다리 오염 바닥 52.8 → 61.4, 바퀴 모래는 견인 상한 0.3을 넘는 예측(게이트) → 상한 안(64.1, 51.4), 고급 바퀴의 풀밭 15°는 "오를 수 있음" → "미끄러져 못 오름"(건너뜀), 마모는 채취 1시간에 수명 900%(가정) → 0.008%(중급)·0.0003%(고급). 홀드아웃 통과는 줄어든 곳 없음(중급 바퀴·트랙 0 → 4/8, 고급 트랙 0 → 2/6). 점수가 오른 이유가 "닮아서"인지 "답할 수 있게 돼서"인지는 연구 문서 6장에 나눠 적었다.

## 7. 검증

- 단위·통합 시험: `cargo test --workspace` (noto-core 효과·지면·마모, world-sim 지면·경로·마모·리셋, noto-runtime 내려놓기·왕복·쪼개기·리셋·험지 탐색·라이브 기록·물리 상태·SDS).
- 브라우저(개발 서버): 툴바에서 명령 실행 → 타임라인 1–3줄 기록과 라이브 월드 복귀, 인벤토리 내려놓기 버튼, "베이스캠프에 다 내려놔" → 더미 표시, 월드 리셋(더미 비움·배터리 유지)과 신체 상태 리셋(배터리 100%), 3인칭 화면.

## 8. 한계

- 지면 표의 일부(풀밭의 발·트랙 μ, 젖은 모래의 발 μ·η, 트랙 Crr, 메카넘 계수)는 추정이다. 바퀴의 미끄러짐률별 추력이 없어 모래 위 바퀴 견인을 실제보다 높게 본다(0.25 vs 0.05–0.08).
- 마모의 정격은 STS3215 시험(서보), Harmonic Drive(유성 QDD 대입), Nabtesco(사이클로이드)이고 관절 속도 항을 1로 둔다. 충격(타격) 피크 횟수는 세지 않는다.
- 바퀴·트랙 시나리오는 독립 기준이 적어 점수가 대부분 자세 안정 셀(사람 기준)에서 온다.
- 이동 시간은 여전히 가감속을 반영하지 않고, 지면은 속도를 바꾸지 않는다(에너지와 통과 여부만).
- 시뮬레이터의 인식은 대역(오라클) 기본이며 ML 수치는 대역 모델의 값이다(v0.4와 같음).
