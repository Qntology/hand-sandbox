작성일 2026-10-24. v0.3([`PLAN-v0.3.md`](PLAN-v0.3.md)) 위에 세 가지를 더했다. 복합 N:N의 근거와 개선 기록은 [`research/nn-scenarios.md`](research/nn-scenarios.md)에 있다. 벤치마크(속도 측정)는 돌리지 않았다.

## 1. GPU

### 1.1 장치

`hand_ml::device`: 시작할 때 이 빌드의 GPU 백엔드를 CUDA → ROCm → Vulkan → Metal 순으로 열어 보고 첫 번째를 쓴다(`HAND_DEVICE=cpu|cuda|rocm|vulkan|metal|gpu[:번호]`로 고정). 모든 모델은 같은 캐시에서 장치를 받는다(이전에는 앱이 CPU로 시작했고 모델을 불러올 때마다 장치를 새로 열었다). 일괄 호출 뒤에는 장치 풀의 남는 메모리를 돌려준다(CUDA·ROCm 256 MB 유지, Vulkan은 64 MB 넘을 때만). Windows에서 ROCm을 쓴 프로세스는 `TerminateProcess`로 끝나 rocBLAS 종료 멈춤을 피한다(commerce `ROCM-EXIT`).

### 1.2 배치 정책 (`BatchPolicy`)

이미지: 패스당 `token_budget / 토큰 수` 장(GPU 2048, CPU 1024), 패딩 없음. 텍스트: CUDA·ROCm은 항상 같은 행 수로 채워(첫 행 복사) 한 문구의 벡터가 같은 호출의 다른 문구에 따라 바뀌지 않게 한다(commerce ⑤). CPU·Vulkan·Metal은 행 수 그대로(⑥). 문구 뱅크의 캐시 공간에 장치 계열과 이 모양을 넣어 CPU·CUDA·ROCm·Vulkan 벡터가 섞이지 않는다.

### 1.3 모델별

| 모델 | 장치 | 배치 |
|---|---|---|
| SigLIP2 비전 (분류·타일) | 선택 장치 | `embed_images`: 패치 격자별로 묶어 정책 행 수 |
| SigLIP2 밀집 (의미 위치) | 〃 | `embed_dense_batch`: 키프레임들을 한 번에, 라벨 문구 벡터는 배치당 한 번 |
| SigLIP2 텍스트 | 〃 | 문구 뱅크(중복 제거·길이 정렬) + CUDA·ROCm 고정 모양 |
| TIPSv2 DPT 깊이 | 〃 | `predict_batch`: 같은 크기 키프레임을 한 번에 인코더·DPT 헤드로 |
| SAM 마스크 (신규) | 〃 | MobileSAM(TinyViT) 또는 SAM ViT-B (`candle-transformers`). 이미지 인코더는 키프레임당 한 번, 다가올 키프레임을 `prepare`로 일괄 인코딩해 장치에 캐시. 한 키프레임의 모든 프롬프트(따라갈 트랙 + 새 프롬프트)는 디코더 한 번. 가중치(`lmz/candle-sam`)가 없으면 영역 확장 추적기 |
| Granite TTM | 〃 | 기존 그대로 |

통합 테스트의 인식 통과는 단계마다 키프레임들의 깊이·의미 위치·SAM 인코딩을 먼저 일괄 계산하고(`MlPipeline::prefetch`), 추적만 순서대로 한다.

### 1.4 검증 (이 PC: RTX 3050 Laptop 4 GB, CUDA 13.3, 드라이버 610.62)

`test_cuda.bat -p hand-vision --test gpu_backend`: 같은 무작위 가중치로 CPU와 CUDA 결과 비교. SigLIP2 이미지·밀집·텍스트 상대 오차 ≤ 2.2e-7, TIPS 일괄 3.3e-6 (단일 대 일괄 행 2.4e-6), SAM 인코더 7.7e-5 · 디코더 5.4e-5 · IoU 6.1e-6. 이 시험이 실제 버그를 찾았다: `candle-transformers`의 SAM 마스크 디코더가 비연속 행렬로 matmul을 해 CUDA에서 실패한다(CPU는 통과). 디코더를 `hand-vision/src/sam_decoder.rs`로 가져와 행을 연속으로 만들었다. 또 SAM의 LayerNorm2d는 가중치 기본값이 0이라 무작위 가중치 비교가 무의미했던 것을 시험에서 바로잡았다.

ROCm(이 PC에 AMD GPU 없음)과 Vulkan은 빌드 스크립트와 기능 플래그만 준비했고 실행 검증은 하지 않았다. `check_cuda.bat`(작업 공간 전체 CUDA 빌드)은 통과.

## 2. 관절 동역학과 3인칭 뷰

`hand_core::dynamics`: 프리셋으로 만든 상체 강체 트리(골반 → 허리 요 → 허리 피치 또는 강체 → 가슴 → 목·머리, 어깨·팔꿈치·손). 질량·CoM은 프리셋 값(`balance`와 같은 분할), 관성은 그려지는 상자의 값(추정). `M(q)q̈ = τ − h`를 RNEA(재귀 뉴턴–오일러)와 그 열로 만든 질량 행렬로 풀고 2 ms 반암시적 오일러로 적분. 관절마다 프리셋 액추에이터의 토크–속도 직선으로 자른 계산 토크 제어, 역구동 불가 서보는 과부하에 밀리지 않고 멈춘다. 다리와 바퀴는 전신 뉴턴–오일러 합인 지면 반력의 정역학으로 토크를 낸다. 동적 ZMP·여유·머리 기울기·골반 좌우 가속을 기록한다.

정합성 시험: 정지 토크가 준정적 모델과 3% 안, 정지 상태의 ZMP = CoM 투영, 수동 진자의 에너지 보존 2% 안, 출발 시 ZMP 관성 이동 `x_com − z·a/g`, 보급형 팔꿈치(STS3215)는 원목에서 멈추고 중급은 든다, 체중 이동 뒤 발 들기.

월드는 자세가 바뀔 때마다 이 전이를 시뮬레이션하고(`World::motion`), 3인칭 뷰(`world_frame` view `chase:<궤도각>`)는 레이캐스터에 로봇 링크를 방향 있는 상자로 그려 넣고, 관절·CoM·ZMP·지지면·반력 화살표를 픽셀로 투영해 돌려준다. UI 시점 선택의 "3인칭 (관절 물리)"이 이것을 그리고, 오른쪽 아래 패널에 이번 자세 변화의 관절별 토크/피크 시계열과 관절 표가 나온다. 1인칭 카메라는 ML 로직이 보는 그대로 둔다.

## 4. 복합 N:N

시나리오·가중치·채점·벤치맥싱 방지 장치는 [`research/nn-scenarios.md`](research/nn-scenarios.md). 기존 시험과의 관계:

- 퀘스트 실행 중 월드의 각 밸런스 상태가 원인 집합으로 시나리오 위상에 대응되고(예: 짐 실은 채 이동 끝 제동 → S4 제동 단계), 그 시나리오의 가중치로 채점돼 SDS(`balance|nn:S4|brake_1.5`)와 `nn_status`에 쌓인다. `scenarios`·`integrated` 시험이 이를 확인하고 `[NN-SUM]`을 출력한다.
- `nn_scenarios` 시험은 시나리오 라이브러리 전체를 프리셋 4종 × 베이스 2종으로 돌려 셀 원값·기준·z를 남기고, 점수 문턱이 아니라 채점 장치와 벤치맥싱 방지 규칙만 검사한다.

이번에 고친 물리·제어(모두 기준값과 무관한 원리):

1. 두 발 → 한 발: 체중 이동이 끝난 뒤 발을 든다(지지면 전환 시점).
2. 주행 계획기: 출발은 뒤쪽, 제동은 앞쪽 지지면 끝까지의 여유와 경사·견인력으로 따로 정한다. 이동 끝에 제동 구간을 둔다(이전에는 제동이 모델에 없었다).
3. 자세 변화가 끝난 뒤 가감속을 시작하고, 허리 피치가 있으면 가속 전·중 여유가 같도록(minimax) 기울인다.

효과: 바퀴형 경사 출발(S6)이 중급·고급·고급 팔에서 게이트(뒤로 넘어짐) → 79.9–84.0점, 고급 다리가 2.5 m/s² 제동까지 내딛지 않음, 홀드아웃은 줄어든 곳 없이 고급 다리 1 → 2/8.

## 5. 한계

- GPU: CUDA만 이 PC에서 실행 검증. ROCm·Vulkan은 미검증. 모델은 F32(commerce처럼 CUDA·ROCm에서 BF16을 쓰면 메모리가 줄지만 수치 검증이 필요해 미적용). SAM·TIPS·SigLIP2 실제 가중치로 수치를 비교하지 않았다(가중치 없음).
- 동역학: 다리는 정역학, 관절 마찰·회전자 관성·전류 루프 지연 없음, 멈춘 서보의 기어는 어떤 하중도 버틴다고 가정, 상자 관성. 월드의 이동 시간은 가감속을 반영하지 않는다(제동은 밸런스 상태로만 들어간다).
- 3인칭 뷰는 사람을 위한 것이라 ID·깊이 버퍼의 로봇 픽셀은 ML 평가에 쓰지 않는다.
- N:N: S5(주파수 응답)는 미구현. 유도 기준의 허용폭은 레포 관례(±30%)나 선택값. 시나리오 점수는 사람다움이지 성능 순위가 아니다.
