## 1. SDS 중심 설계

SDS는 v0.2에서 인식 점수의 원장이었다. v0.3에서는 테스트 전체의 원장이다. 기록 방식은 그대로(Welford 평균·분산 + 최근값 링, `트랙|primary|secondary` 스코프 폴백, 원자적 저장)이고, 트랙과 원장 파일이 늘었다.

| 원장 파일 | 트랙 | primary | secondary | 축(예) | 누가 다시 읽나 |
| --- | --- | --- | --- | --- | --- |
| `ml.json` | `depth` | 깊이 모드 | 라벨 | `absrel`, `delta1`(평가), `scale`(보정: 삼각 측량 거리 / 깊이 거리) | 결정 단계: 학습된 깊이 축척으로 거리 추정을 고친다 |
| | `locate` | 라벨 | 모드 | `score`, `margin`, `presence`, `err_px`(평가) | 결정 단계: 라벨별 점수 기준선 아래의 위치는 프롬프트로 쓰지 않는다 |
| | `tracker` | 라벨 | 모드 | `iou_prev`, `area_frac`, `score`, `iou_truth`(평가), 일치율 `alive` | 추적 신뢰도 |
| | `decide` | 결정 종류 | 베이스 | `residual_deg`(예측 방위 − 관측 방위), `tri_sigma_frac`, 일치율 `arrived` | 다음 결정의 예측 띠 |
| | `fusion` | 라벨 | — | `peak_in_mask`, `peak_depth_gap`, `heat_in_mask`, `range_gap`, `motion_residual_deg`, `head_tilt_deg` | 키프레임마다 z-점수로 이상 표시(타임라인 SDS 레인) |
| `body.json` | `balance` | `원인>대상`(예: `arm_lift>belly`) | 지형·단계(예: `flat|pick`) | N:N 셀 값 + 리서치 기준 대비 `:dev`·`:in_band`, 보정 `ff`(실제 / 예측 교란) | 피드포워드 이득 |
| | `effort` | 부위 | 상태 | `peak_ratio`, `effort`, `torque_nm` | 프리셋 비교 |
| `task.json` | `quest` | `pass|kind` | 단계 | 일치율 `success` | 성공률(백오프 포함) |

### 1.1 ML 트랙이 서로를 고치는 방식

1. **깊이 축척 학습(정답 없이)**: TIPSv2 DPT는 NYUv2(실내)로 학습되어 0.001–10 m만 낸다. 삼각 측량으로 얻은 미터 거리 / 깊이 모델 거리를 `depth|<mode>|<label>`의 `scale` 보정으로 쌓는다. 다음 키프레임부터는 `calibration_factor`가 깊이 거리를 고친다.
2. **의미 위치 → 추적 프롬프트**: SigLIP2 피크 점수가 SDS 기준선(평균 − k·표준편차) 아래면 SAM식 추적기에 프롬프트로 주지 않는다. 기준선이 생기기 전(냉간 시작)은 고정 하한을 쓴다.
3. **혼합 특징**: 피크가 마스크 안에 있는지, 피크의 깊이와 마스크 중앙값 깊이가 같은 물체인지, 히트맵 질량이 마스크에 담기는지, 깊이×축척 거리와 삼각 측량 거리가 맞는지, 이동 후 예측 방위가 맞는지, 몸의 기울기가 카메라에 얼마나 전달됐는지. 라벨별 기준선을 SDS가 배우고, 벗어나면 표시한다.
4. **혼합 특징이 결정을 막는다**: 도달(손을 뻗기) 직전에 의미 피크가 추적 마스크 밖이면(`peak_off_mask`) 도달하지 않고 추적을 다시 시작한다. 영역 확장 추적기는 옆 물체(나무 옆 바위)로 번지는 일이 있는데, 이 문 하나로 시드 7 시험에서 헛 채취가 1회 → 0회로 줄었다(접촉 확인 정밀도 0.5 → 1.0). 결과는 `fusion|<label>|`의 `commit_ok` 일치율로 쌓인다.

### 1.2 시계열 모델

`hand-ts`의 융합 예측(last·EWMA·Holt, 가중치가 있으면 Granite TTM-R3)을 결정 단계에 쓴다. 대상 위치(삼각 측량 점)의 시계열을 예측해 그 예측값으로 움직이고, 새 측량점이 P10–P90 띠를 벗어나면 따르지 않고 다시 측량한다(`hold(band)`). 이동 뒤에는 "다음 키프레임에서 대상이 정면에 보여야 한다"는 예측을 남기고, 다음 키프레임의 잔차가 `decide` 트랙에 쌓인다.

### 1.3 N:N 밸런스

원인 동작 7가지 × 대상 부위 7가지. 원인: `arm_raise`(채취 타격), `arm_lift`(들어올리기), `foot_lift`(보행 중 한 발), `step_up`(턱), `slope`(경사), `carry_front`(앞쪽 적재), `accel`(가감속). 대상: 머리·가슴·배·팔·손·다리·발.

셀 값은 모두 차원 없는 값이다: CoM 이동 / 발 길이, 관절 토크 / 피크 토크, 회복 비율, 좌우 이동 / 반 보폭, 머리 잔여 기울기(°), 안정 여유(지지면 반길이 비율). 사람 기준값(유도 포함)은 `hand_core::balance::reference`에 있고, 짐이 있는 동작은 하중/체중 비율로 선형 보정한다. 예:

- `arm_raise > arm.peak_ratio` 기준 0.15 ± 0.05 (어깨 최대의 ~15%)
- `arm_lift > belly.restore_frac` 기준 0.2 → 0.9 (5 kg에서 골반·몸통이 CoM을 거의 다 되돌림)
- `foot_lift > belly.shift_frac` 1.0 ± 0.2 (CoM이 지지 발 위로), `foot_lift > leg.peak_ratio` 0.55 ± 0.10
- `step_up > leg.peak_ratio` 0.46 ± 0.10, 머리 기울기 0 ± 8.5°
- `slope > foot.cop_shift_frac` 발끝 올림 −0.6%/°, 발끝 내림 +0.8%/°

로봇 값이 기준 띠를 벗어나는 것은 숨기지 않는다. 예를 들어 중급 다리의 고관절 노력은 사람(50–60%)보다 훨씬 낮다(Robstride 03이 체중 대비 강함). 이것이 "더 싼 액추에이터로 충분하다"는 가성비 판단의 근거가 된다.

**개선 고리**: 제어기의 피드포워드(사람의 예측 자세 조절, APA)는 사람 비율 모델(팔 = 체중의 5%, Winter)로 교란을 예측한다. 실제 프리셋은 비율이 달라 예측이 틀린다. 반응만으로 고치면 전기기계 지연(100 ms)만큼 늦어 여유가 줄고 보상 관절 노력이 커진다. SDS가 `balance|<원인>>foot|*`의 `ff` 보정(실제 교란 / 예측 교란)을 배우고, 그 값이 다음 동작의 피드포워드 이득이 된다. DB `balance_effort`에는 같은 상태에서 피드포워드 있음/없음의 노력과 여유가 나란히 남아 개선량이 보인다.

## 2. 게임 로직과 ML 로직의 경계

```
게임 로직 (world-sim, hand-quest, hand-runtime driver)
  월드 · 물리(프리셋, 밸런스) · 퀘스트 실행 · 렌더(RGB + 정답 ID/깊이)
        │ 키프레임: WebP, 카메라 내부값, 주행 거리계 자세, 시각
        ▼
ML 로직 (hand-vision)
  깊이(TIPSv2 DPT) → 의미 위치(SigLIP2) → 마스크 추적(SAM 3.1 인터페이스) → 삼각 측량 → 시계열 결정
        │ 결정: 회전 / 삼각 측량 이동 / 접근 / 도달
        ▼
게임 로직이 실행(경로 계획·물리 제약) → 다시 촬영
```

정답 버퍼(ID·깊이)는 키프레임에 1/2 해상도로 함께 저장하지만 평가 열과 SDS 평가 축에만 쓴다. 가중치가 없을 때 쓰는 대역 모델(깊이·의미 위치)은 정답에 일부러 오류를 섞은 것이며, 그 사실을 모드 이름(`stand-in`)과 로그에 남긴다. 마스크 추적의 대역(`region-grow`)은 정답을 쓰지 않는다(이미지와 깊이만으로 영역을 키운다).

## 3. 통합 테스트 흐름 (세 번의 통과)

1. **게임 통과**: 같은 시드·프리셋으로 명령(예: "철광석 2개 캐서 창고로 가져와")을 게임 로직 실행기로 끝까지 수행. 영상과 고정 키프레임을 기록하고, 퀘스트·단계 성공 여부와 밸런스 사건을 기록.
2. **ML 인식 통과**: 게임 키프레임마다 깊이 → 의미 위치 → 추적(키프레임 순서대로 같은 추적기). 연속 키프레임의 자세 차이로 기회적 삼각 측량도 해 본다. 타임라인 2줄.
3. **ML 결정 통과**: 같은 시드로 월드를 다시 만들고, ML 결정이 탐색·접근을 맡는 폐루프로 같은 퀘스트를 수행: 촬영 → ML 파이프라인 → 삼각 측량/예측 → 결정 → 게임이 이동 → 촬영. 채취·줍기·운반·인도는 게임의 동작을 그대로 쓰되 물리 판정(들기·밸런스)을 통과해야 한다. 타임라인 3줄.

각 통과는 `TestDb`에 퀘스트 한 줄과 단계별 시도·성공을 남긴다. `pass` 열(`game`/`ml`)로 나뉘어 성공률을 비교한다.

## 5. 의무 삼각 측량

단안 깊이는 방향은 정확하고 거리는 부정확하다(특히 TIPSv2는 10 m에서 잘리고 실내 축척이다). 그래서 ML 결정의 규칙은:

- 대상이 처음 추적되면 거리 추정이 확정될 때까지 **삼각 측량 이동**을 한다. 필요한 수직 기선은 `r̂ · tan(γ_min · 1.4)`(γ_min = 6°, 거리 추정 r̂은 깊이 × 학습된 축척). 옆으로 갈 수 있는 베이스(메카넘)는 옆걸음, 아닌 베이스는 시선에서 55° 벗어난 방향으로 이동한 뒤 추정 위치를 바라본다.
- 같은 추적 ID의 방위를 최소 제곱으로 교차한다(`Σ(I − uuᵀ)p = Σ(I − uuᵀ)pᵢ`). 오차 모델 `σ_r ≈ r·σθ·√2 / sin γ`가 거리의 15% 이하가 될 때까지 같은 방향으로 기선을 더한다.
- 확정되면 시계열 예측 위치로 최대 3 m씩 접근한다. 새 측량점이 예측 띠를 벗어나면 다시 측량한다.
- 측량 거리 / 깊이 거리 = 깊이 축척 → SDS `depth` 보정. 단, **광선 3개 이상이 0.15 m 안에서 만나고**, 오차가 거리의 15% 이하이며, 거리가 1.5–9 m일 때만 쓴다(`scale_usable`). 광선 2개는 한쪽이 다른 물체를 봐도 언제나 한 점에서 만나서, 추적이 바뀐 경우를 걸러 낼 수 없다.
- 가까워지면(깊이 × 축척 ≤ 1.6 m) 깊이 거리로 바로 판단한다. 1 m 근처에서는 거리의 15% 기준이 너무 엄격해 삼각 측량을 반복하게 되고, 이 거리에서 깊이 오차는 수 cm이기 때문이다.
- 도달 판단은 보이는 표면 기준이다(노드 중심은 그 뒤에 있음). 손이 닿는 노드 가운데 **추정 위치에 가장 가까운** 것을 만진다(로봇에 가장 가까운 것이 아니라).

## 6. 물리: 부품 프리셋과 밸런스

로봇은 약 1.2 m(고관절 0.58, 허리 0.70, 어깨 1.00 m). 부위마다 보급/중급/고급(다리는 보급+ 추가) 프리셋이 있고 값은 데이터시트에서 왔다(`research/parts.md`). 모습은 마인크래프트식 그대로지만 물리에는 다음이 반영된다.

| 무엇이 | 무엇에서 | 예 |
| --- | --- | --- |
| 들 수 있는지 | 들어올리는 순간(위팔 30°, 아래팔 수평)의 어깨·팔꿈치 토크 ≤ 피크, 균형 여유 ≥ 0, 한 팔이 안 되면 두 팔로 나눠 들기(시간 1.5배) | 보급형 팔꿈치(STS3215 2.94 N·m)는 원목 2.4 kg을 못 든다. 중급은 철광석 4 kg을 두 팔로, 고급은 한 팔로 |
| 속도 | 다리: Froude 수, 무릎 연속 토크 대비 필요 토크(부족하면 제곱 감속). 바퀴: 섀시 최고 속도, 0.5 m 안에 멈출 수 있는 감속(ZMP 여유) | 보급형 다리는 거의 못 걷는다(무릎 피크 < 1.5 × 필요). 짐을 실을수록 느려진다 |
| 경사 | 바퀴: 구동력, 넘어지지 않는 각(키 큰 로봇 + 짧은 바퀴 간 거리), 허리 피치 관절이 있으면 기울여 보상. 다리: 발바닥 마찰 | 허리가 요(yaw)만 있는 보급·중급은 기울일 수 없어 경사 한계가 낮다 |
| 턱 | 무릎 피크로 밀어 올릴 수 있는 높이(`1.5·m·g·d(h) ≤ τ_peak`) | 보급+ 다리는 10 cm 연석을 못 넘는다 |
| 적재 | 다리 연속 지지 질량 − 로봇 질량, 섀시 구조 한계 − 상체 질량 | 중급 이족은 약 4 kg만 상시 운반 |
| 배터리·에너지 | 가슴 프리셋의 Wh, 구동 전력은 질량 비례 | |
| 채취 속도 | 팔 관절 발열(τ/τ_cont)² 모델, 열이 차면 감액 | 보급형 팔은 오래 캐면 느려진다 |

밸런스 모델은 준정적이다: 점 질량, CoM과 ZMP, 지지 다각형 여유, 관절 토크, 발목 전략(작은 이동은 발목) → 몸통 기울임(큰 이동, 허리 피치 관절이 있을 때) → 한 발 들기에서 골반을 지지 발 위로. 단순화(관절 각도 한계는 몸통 기울임만, 발 회전 없음, 카메라 높이는 렌더러 값)는 코드 머리 주석과 이 문서에 적는다.
